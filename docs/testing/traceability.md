# Traceability

Which tests prove which feature ([feature catalogue](../reference/features.md)) and which security control ([threat model](../security/threat-model.md)). Files are under `tests/`. Quoted text is an exact `describe` or test name; unquoted text in parentheses is a short label for a test in that file.

## Threats and ASVS chapters → tests

| Threat (boundary)                                   | ASVS chapter | Test                                                                                                                                                                                                                                                                                                                                                                                                          |
| --------------------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Malformed or hostile import file (B1, T)            | V2, V5       | `document.test.ts` "rejects ids with unsafe characters, duplicate ids and dangling group references", "reports schema problems with their path", "rejects a group id that is also an item id", "rejects a grid step below 1 cm, which would make snapping and the grid degenerate", "accepts repeated tags and keeps one of each"; `editor.spec.ts` "rejects an invalid import and leaves the plan untouched" |
| Migrated values outside the bounds (B1, T)          | V2           | `document.test.ts` "checks the upgraded plan against the current bounds as well"                                                                                                                                                                                                                                                                                                                              |
| Prototype pollution through keys (B1, T/E)          | V2           | `document.test.ts` `drops unknown keys, including "__proto__", without touching any prototype`                                                                                                                                                                                                                                                                                                                |
| XSS through names or titles (B1/B2, E)              | V1, V3       | `site.spec.ts` "markup in names is shown as text and never runs"                                                                                                                                                                                                                                                                                                                                              |
| Oversized file, huge arrays, error flood (B1, D)    | V2, V5       | `document.test.ts` "accepts files up to the limit and rejects larger ones before reading them", "rejects oversized documents", "caps the error list so a hostile file cannot flood the dialog"; `editor.spec.ts` "renders only visible items on the 3,000-desk stress floor"                                                                                                                                  |
| Tampered or corrupt storage (B2, T)                 | V2, V14      | `plan-store.test.ts` "backs up an unreadable plan before the demo replaces it"; `site.spec.ts` "a corrupt saved plan falls back to the demo and is kept as a backup"                                                                                                                                                                                                                                          |
| Writing a plan the loader rejects (B2, T)           | V2, V14      | `seed-storage-culling.test.ts` "refuses to save a plan the loader would reject, keeping the good one"; `editor.test.ts` "limits of the file format", "mints distinct, valid ids after ids with huge numeric suffixes, so autosave keeps working"                                                                                                                                                              |
| Storage full or blocked (B2, D)                     | V16          | `editor-page.test.tsx` "shows and announces a failed save", "says so when browser storage cannot be used at all"                                                                                                                                                                                                                                                                                              |
| Script injection, unsafe eval, inline code (B3, E)  | V3           | `site.spec.ts` "runs under the strict Content Security Policy without violations"; every end-to-end test (console-error check)                                                                                                                                                                                                                                                                                |
| Data leaving the origin (B3, I)                     | V3, V14      | `site.spec.ts` "runs under the strict Content Security Policy without violations" (no off-origin requests)                                                                                                                                                                                                                                                                                                    |
| Framing, MIME sniffing, cross-origin access (B3, T) | V3           | `site.spec.ts` "sends the security headers, and the built page carries the policy as well" (also checks the CSP `<meta>` is the second element in `<head>`)                                                                                                                                                                                                                                                   |
